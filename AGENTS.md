# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

IntraFlow — a macOS-first desktop tool that redirects public tunnel domains to
internal LAN addresses via local hosts hijack + TCP port forwarding. It lets
you access intranet services without routing through the public tunnel.

## Stack & constraints

- **Language**: Go 1.23+ (backend), vanilla JS + Vite (frontend). No frameworks
  on the frontend (no React/Vue).
- **GUI**: Wails v2 (system WKWebView on macOS, not Electron).
- **Tray**: `github.com/cardinalby/go-systray` — a fork of fyne-io/systray that
  renamed the ObjC `AppDelegate` class to `TrayIconAppDelegate` to avoid a
  duplicate-symbol linker conflict with Wails. **Do NOT switch back to
  getlantern/systray or fyne-io/systray — they break the build on macOS.**
- **Stdlib-first**: internal packages use only the standard library unless a
  dep is already in go.mod. Don't add deps without a clear reason.

## Critical architecture: dual-process

Two processes, one binary:

```
intraflow           → host: tray + orchestrator + IPC server (no window)
intraflow --gui     → GUI: Wails webview + IPC client (spawned on demand)
```

- `main.go` (`!bindings`) — flag dispatcher.
- `host.go` (`!bindings`) — host entry: orchestrator, IPC server, tray, GUI spawn.
- `gui.go` (`!bindings`) — GUI entry: IPC dial + wails.Run.
- `app.go` — Wails-bound App facade; methods are thin IPC shims.
- `main_bindings.go` (`bindings` tag) — Wails binding-generation entry. **Must
  NOT acquire the single-instance lock or run wails.Run** — the bindings-mode
  binary is run during `wails build` and would hang.

**The host must never call osascript.** It's a background menu-bar daemon; the
macOS admin dialog can't attach to it (osascript errors -128). All elevated
hosts writes go through the GUI process via a two-phase IPC flow:
`PrepareX` (host validates + builds content, no elevation) → GUI runs
`hosts.WriteHostsElevated` → `CompleteX` (host finalizes).

## Packages (internal/)

- `config` — Domain/Forward/Config structs, JSON persistence to
  `~/.intraflow/config.json` (atomic writes), validation (domain unique
  case-insensitive, listen port unique, host non-empty, ports 1-65535).
  Unparseable or legacy (`records`-keyed) config is reset to a fresh empty
  config — no migration.
- `forwarder` — TCP forwarder (transparent pipe, per-connection dial to the
  cached target), Pool keyed by forward ID, target DNS resolution: resolve at
  start once, refresh every `dnsRefreshMinutes` (default 5), and re-resolve +
  retry once on dial failure (bounded staleness). Literal-IP targets skip
  resolution. Status (`StatusInfo`) carries State/Reason/ResolvedIP.
- `hosts` — hosts file read/write with `# BEGIN/END IntraFlow` marker zone,
  consistency check, elevated write via osascript (darwin) / pkexec+sudo
  (linux) / PowerShell `Start-Process -Verb RunAs` (windows, native UAC dialog).
  The Windows copy script is passed via `-EncodedCommand` (UTF-16LE base64) so
  paths need no shell escaping; UAC decline surfaces as exit code 1223, which
  `runElevated` maps to `ErrElevationCancelled`.
- `orchestrator` — ties config+hosts+forwarder together; Prepare/Complete pairs
  for ApplyAll/Pause/Resume/FixNow (single-record Save/Disable/Delete are gone).
  Effective forward state = `!settings.Paused && forward.Enabled`; hosts zone =
  paused ? empty : domains. All elevated writes are split (host never writes
  hosts itself).
- `ipc` — newline-delimited JSON protocol over unix socket `~/.intraflow/ipc.sock`;
  Request/Response + server→client push Events (recordsChanged, openSettings,
  elevatePause/elevateResume, confirmQuit). DTOs are the camelCase shapes
  (`DomainDTO`/`ForwardDTO`/`StatusInfoDTO{state,reason,resolvedIP}`/`SettingsDTO`).
- `runtime` — systray wrapper (menu build/rebuild via ResetMenu; global-only
  menu: title summary / 打开主界面 / 设置 / 暂停·恢复托管 / 退出 — no per-record
  items, no autostart item), autostart (macOS 13+: `SMAppService.mainApp`,
  live system status is the single source of truth — never persist it in config;
  fallback LaunchAgent via `launchctl bootstrap gui/<uid>`; Windows reg.exe /
  Linux .desktop), single-instance lock, activation policy bridge.

## Frontend

- `frontend/src/main.js` — all UI logic: two inline-editable tables (托管域名 +
  端口转发, no add/edit modal), settings, draft model, global pause UI, quit-confirm
  modal.
- `frontend/src/style.css` — all styles, macOS-native look, dark mode support.
- `frontend/wailsjs/` — GENERATED by `wails build`. Do not hand-edit.
- Draft model: panel stages all edits locally (draft), "保存并生效" calls
  `SaveAll({domains, forwards})` once → at most one password prompt (skipped
  entirely if hosts content is unchanged). Forward enable toggles are staged too.

## Build & test

```bash
wails dev          # live dev (hot reload)
go build ./...     # compile check
go build -tags bindings ./...   # bindings mode must also compile
go test ./internal/...          # unit + e2e tests
scripts/build-macos.sh  # package macOS app with native icon → build/bin/intraflow.app
```

The macOS wrapper requires Xcode's `actool`; it adds `Assets.car` to the Wails
bundle and re-signs it. Plain `wails build` does not update this icon resource.

**Before packaging**: kill stray processes and clear locks, otherwise the
bindings-mode binary can hang on the single-instance lock:

```bash
pkill -9 -f "intraflow|wailsbindings"; rm -f ~/.intraflow/intraflow.lock ~/.intraflow/ipc.sock
```

## Gotchas (learned the hard way)

- **Port fields are numbers.** The frontend DOM `.value` returns strings; the
  Go DTOs (`ForwardDTO` etc.) have `int` ports. Always `Number()`-coerce before
  sending over Wails — string→int makes JSON unmarshal fail and the JS promise
  reject with a generic error.
- **Wails event names are camelCase.** Go emits and the frontend
  `EventsOn`s the SAME names (`recordsChanged`, `openSettings`, `confirmQuit`,
  ...). Keep them identical — a kebab/camel mismatch drops the event silently
  (the panel stops tracking tray pause/resume).
- **Spawn-flag modals use pull, not push.** A GUI spawned with a flag
  (`--open-settings`, `--confirm-quit`, `--elevate=`) must NOT
  `EventsEmit` from onDomReady — it races the JS `EventsOn` registration. Read
  the one-shot Wails binding `PendingAction()` from the frontend after init
  instead. Push (IPC event → Wails event) is only safe for an already-running GUI.
- **osascript quoting**: use single quotes for shell paths inside `do shell
  script "..."` — double quotes need AppleScript escaping (`\"`) which breaks
  with a syntax error on non-English system locales.
- **systray ordering**: systray only appends menu items. To reorder/relabel,
  call `ResetMenu()` and rebuild the whole menu each refresh.
- **Single-instance lock breaks `wails build`** if acquired in bindings mode —
  that's why `main_bindings.go` exists.

## Testing expectations

- New backend logic → add tests in the same package (`*_test.go`).
- Keep the E2E tests in `internal/orchestrator/e2e_test.go` green; they
  exercise the full pipeline (config → hosts zone build → forwarder → real TCP
  server) without real elevation.
- Don't touch the real `/etc/hosts` in tests — use the injectable
  `readHosts`/`writeHosts` hooks (`orchestrator.NewForTesting`).
